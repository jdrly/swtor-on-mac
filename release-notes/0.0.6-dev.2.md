## SWTOR on Mac 0.0.6-dev.2 (development build)

A test build of the next version, for measuring before a release. It is not offered as an
update; install it by hand. The next public version (0.0.6) is offered over it as usual.

**What's new since 0.0.6-dev.1 (d9mt `c045221`, branch `dev`):**
- **Fewer attachment re-clears.** 0.0.6-dev.1 re-cleared about 2 render targets per frame
  whose clear it had skipped storing, because something read them later. The likely cause is
  SWTOR's 2048×2048 shadow atlas: its stencil is cleared but never drawn, and sampling the atlas
  as a shadow map re-cleared it, depth included. Sampling now reads only depth, and a target
  that is read after its clear every frame keeps its store instead of a re-clear each frame.
  Visuals stay the same.
- **`RESTORE` lines** with Debug Logging: in each second with re-clears, which images (format,
  size), why and from which Direct3D call. `session-report.sh` sums them up by cause.
- **Live d9mt flags.** With Debug Logging on, d9mt reads
  `~/Library/Application Support/SWTOR on Mac/prefix/drive_c/d9mt/flags.txt` once a second
  while the game runs. `no_attach_opt` turns the load/store optimization off and on live,
  `att_trace` logs its decisions (the file lists the flags).

**Development build:**
- A *Development build* badge in the window and in About.
- **Debug Logging is on by default.** It costs a little performance; turn it off in Settings if
  you like.
- No automatic update checks. *Check for Updates…* works.
- `session-report.sh` (in the app's Resources, also in Collect Logs) sums up a session and
  compares two:

  ```
  R="/Applications/SWTOR on Mac.app/Contents/Resources"
  "$R/session-report.sh" --keep              # the last session, and keep a copy of its log
  "$R/session-report.sh" --compare A.log B.log
  ```

To install: quit SWTOR, copy the app from the DMG over the one in Applications, open it, and
click *Update to 0.0.6-dev.2* (Reinstall).
