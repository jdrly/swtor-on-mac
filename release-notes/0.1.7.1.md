## SWTOR on Mac 0.1.7.1

New installs work again: the Wine engine now downloads from a copy of athei's release.

### The engine download is fixed
athei's release of the Wine engine went offline, so a new install stopped at the engine's
download with an error. The same file, byte for byte, is now in
[jdrly/wine-engine](https://github.com/jdrly/wine-engine/releases/tag/cx-26.3.0-8), next to the
Wine source it was built from. athei built it from CodeWeavers' CrossOver 26.3 sources, and the
app still checks it against the same size and sha256. An install that already has the engine
doesn't change and downloads nothing.

### A wrong file in the downloads folder
If the file in `~/Library/Caches/SWTOR on Mac/downloads` under the engine's name isn't the
engine, the window now says so, with the file's size and the start of its sha256 next to the
engine's. SWTOR on Mac renames it to `<name>.wrong` and downloads the engine itself. Before, it
deleted the file without a word. If the download still fails, the message names the address
that works and the exact size and sha256 the file must have.

### Collect Logs reads macOS 27's panic reports
On macOS 27 a kernel panic report has a plain-text *System Profile* after its JSON, and
*Collect Logs…* left such a report out of `system-reports/` as unreadable. It now reads the JSON
and leaves the System Profile out.

Nothing else changes: the graphics driver and your compiled shaders are the same as in 0.1.7. If
you're updating from 0.1.6 or older, 0.1.7.1 also brings everything in
[0.1.7](https://github.com/jdrly/swtor-on-mac/releases/tag/v0.1.7).

### After updating
If your install got stuck at the engine's download, choose *SWTOR on Mac > Check for Updates…*,
install 0.1.7.1, and click *Install SWTOR on Mac* again. If you already have SWTOR on Mac
installed, click *Update to 0.1.7.1* in the window, with the launcher and the game closed.
